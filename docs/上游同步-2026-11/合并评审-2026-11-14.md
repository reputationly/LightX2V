## 3. 冲突逐条

### 3.1 `lightx2v/models/runners/relayvsr/relayvsr_runner.py`

**① 预热尺寸来源(约 124 行)**

| | 内容 |
|---|---|
| 我们 | `for height, width in self.warmup_resolutions():` —— 读配置 `warmup_resolutions`(Pika H3 的 11 个宽高比),没配就回落到类属性 |
| 上游 `#1700` | `for height, width in self._WARMUP_SHAPES:` —— 只有两组代表尺寸,不读配置 |
| 结论 | 取我们。类属性已被上游改名为 `_WARMUP_SHAPES`,所以 `warmup_resolutions()` 的回落值同步改成 `self._WARMUP_SHAPES`(否则 AttributeError)。==上游契约 + 我们的多比例覆盖== |

**② 预热实现(约 185 行)**

| | 内容 |
|---|---|
| 我们 | `_warmup_exact()`(精确块并行专用:11 尺寸 × 每种 rank 布局,含长布局与 `W = k*world` 短布局)+ `_write_synthetic_video()` 造合成源片 |
| 上游 `#1700` | `_prepare_warmup_inputs(height, width)` 钩子 + `create_input_info()` 里的 `validate_sr_ratio()` |
| 结论 | 两边都要:我们的两个方法保留,上游的两个方法追加在其后。非块并行路径(单卡/2 卡 sp)现在走 `_prepare_warmup_inputs()`(上游写法),块并行路径继续走 `_warmup_exact()`。 |

### 3.2 `lightx2v/models/runners/swiftvr/swiftvr_runner.py`

**③ 预热帧张量与 strength(约 155 行)**

| | 内容 |
|---|---|
| 我们 | 手工构造 `torch.zeros(1, frames, 3, h, w, GET_DTYPE)` 并给 `restore_chunk(..., self.video_strength)` |
| 上游 `#1700` | `video = self._prepare_warmup_inputs(h, w, frames)` + `restore_chunk(...)`(上游此时还没 strength 参数) |
| 结论 | 用上游的 `_prepare_warmup_inputs()`(值完全等价,少一份重复代码),**保留**我们的 `self.video_strength` 实参 |

**④ 输出尺寸助手(约 175 行)**

| | 内容 |
|---|---|
| 我们 | `_oriented_target()`(档位按源朝向配对长短边)+ `_clamp_to_ceiling()`(2K 面积上限,兜住显式 `size`) |

### 9.3 全量单测暴露并修掉的一个真问题

镜像内跑 `pytest test_cases`:**1157 passed / 9 failed**,9 个失败全部集中在
`test_cases/test_swiftvr_resolve_output_size.py`。根因是冲突 ④ 的机械合并:上游 `#1700` 把
`@staticmethod` 留在了 `resolve_output_size` 上方,而我们的 `resolve_output_size` 是**实例方法**
(要读 `self.config` 的 `sr_tier_size` / `max_target_*`)。结果 `SwiftVRRunner.resolve_output_size(info, h, w)`
把 `info` 绑给了 `self`,报 `missing 1 required positional argument: 'source_width'`。
修法:删掉那一行 `@staticmethod`(其余 6 处 `@staticmethod` 都是无 `self` 的真静态方法,已逐个核对)。
修后 `test_swiftvr_*` + relayvsr/兼容层/进度过滤 **1005 passed**。

这正是「冲突要逐条看、不能只看能不能 import」的价值:静态检查(`compileall`/`ruff`)发现不了它。
