## 2. WS3 与文档字面不同的一处:`_restore_target_size` 少一个上游守卫

上游是 `if not self.input_info.match_target_size or not self.input_info.size: return sample`,
文档 §WS3.4 只要求前半句 + 保留 HEAD 其余逻辑,**当前实现按文档**。差异仅在
`match_target_size=True` 且完全没配 `size` 时(我们按 720/1280 兜底档位裁/缩,上游原样返回)。
WS5 后所有 SeedVR 配置都是 `match_target_size: false`,上线路径不受影响;若要逐字贴上游,
加 `or not self.input_info.size` 即可(一行)。

## 3. WS4 文档没写、按 HEAD 行为定的三处

1. **warmup 用哪个 strength**:文档只写「图像路径/warmup 也用」。当前 warmup 用 `video_strength`
   (= base × gain),与 HEAD 一致(HEAD 的 warmup 走的就是当年按 base×gain 构建的 restorer)。
2. **`sr_tier_size` 缺省值**:沿用 HEAD 的 (1080, 1920);4 份 SwiftVR 配置都显式配了。
3. **HEAD 的性能埋点未移植**(`stage_seconds`、逐块 `read=/restore=` 计时日志):WS4 清单里没有,
   底版是上游,所以这些 HEAD 独有埋点不复存在。§8.4 的耗时/显存改由外部采样
   (`verify/sr.sh` 的 nvidia-smi 采样 + wall clock)。

## 4. 工具链事实(影响验收执行方式)

- 镜像内**没有** pytest/ruff,机器**无 PyPI 直连**;两者都能从 `mirrors.aliyun.com` 装进一个挂载目录
  (`/data/lx2v-pydeps`),验收脚本 `/data/lx2v-run.sh` 已按 `PYTHONPATH=/opt/pydeps:/repo/dockerfiles/decord_shim:/repo` 组装。
- 镜像自带 `PYTHONPATH=/opt/decord_shim:/opt/LightX2V`;`new` 模式把 `/data/lx2v-sync` 挂到
  `/opt/LightX2V`、`/data/lx2v-sync/dockerfiles/decord_shim` 挂到 `/opt/decord_shim`,
  这样「同一镜像只换代码」,与 `old`(现网 digest cdd5271fe686)构成对照。
- decord 垫片**:镜像里那份是旧的**(没有 `to_dlpack`),所以才要挂我们的 shim —— 这也意味着
  **WS7.1 的 shim 改动只能通过重建镜像生效**,挂载只是验收手段。
