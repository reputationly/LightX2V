## 1. 总原则

1. **白名单保留**:fork 代码只在 §3「保留清单」里的文件中存活;其余所有 `lightx2v/`、`lightx2v_platform/`
   文件合并后必须与 `upstream/main` **逐字节一致**(验收命令见 §8.1)。
2. 框架层(请求生命周期、参数命名 `size/num_frames/fps/video_path`、SP/offload 重构)以上游为准,我们的特性
   **移植到上游新结构上**。
3. 不得每请求修改 `runner.config`(上游已把请求状态放进每次新建的 `InputInfo`)。
4. 每个工作流(WS)单独提交;合并提交只做文本冲突解决 + 白名单外文件回退到上游。
5. **新镜像在验收通过前不得推 `arm64-a100-latest`**:现网 4 个 SeedVR2 副本跟的就是这个浮动 tag,任何容器重启都会
   拉到新镜像(WS7)。

### WS4 SwiftVR(底 = 上游 runner)
新文件 `lightx2v/models/networks/swiftvr/antiphase.py`:HEAD 的 `AntiphaseBlender`(原样含注释)+ 跨 rank carry 函数。

**4.1 恢复强度**:配置 `restoration_strength`(默认 1.0)、`antiphase_strength_gain`(默认 1.4,仅双跑)。上游 runner
里 `latents = model_input - self.model.predict(...)` 乘 `strength`;`SwiftVRRestorer.restore_chunk` 加
`strength: float = 1.0`(图像路径/warmup)。视频 strength = `base * (gain if antiphase else 1)`;**图像永远 `base`**
(单图无时间轴,乘补偿 = 纯过锐;HEAD 的 `restorer_image` 因此不再需要)。

**4.2 输出尺寸** `resolve_output_size`(实例方法)优先级:`input_info.size` > `target_short_edge` > `sr_ratio`
(按 `_oriented_target` 封到配置 `sr_tier_size` 档位,超档出**精确**档位尺寸)。三条路最后都过 `_clamp_to_ceiling`
(`max_target_height/width`,默认 2160/3840,≤0 关闭)。逻辑与注释照搬 HEAD,`target_shape→size`、
`target_height/width→sr_tier_size`。`SRInputInfo.target_short_edge: int = 0`;SwiftVR 字段白名单加
`"target_short_edge"`。

**4.3 反相双跑移植**
- `init_modules`:`antiphase_dual_pass` 时建 `self.restorer_shifted`(同权重、独立状态);上游对
  `self.restorer.autoencoder.chunk_p_group` 赋值/清空、`reset()` 的每一处,对 `restorer_shifted` 同样处理。
- `read_video_frames(..., lead=0)`:索引 `min(max(i, 0), raw-1) for i in range(start - lead, start + n)`;双跑 `lead=1`,
  直相用 `frames[1:]`、移位用 `frames[:-1]`。
- 每个 local chunk 固定顺序:直相 encode → 移位 encode → 直相 predict → 移位 predict → 直相 decode → 移位 decode。
  **所有 rank(含 inactive 的重复块)都按此顺序执行**,保证两套 ring 交换一一配对。
- 双跑时 `decode_chunk(..., output_batch_size=0)`(整块解码再融合);显存代价 1080p 约 2×300MB/块、4K 约 2×1.2GB,
  §8 显存验收确认。
- 融合语义 = `AntiphaseBlender.push`:`direct[i]` 配 `shifted[i+1]`;块末帧作 carry 配下一块 `shifted[0]`;全片
  最后一帧原样输出。
- **跨 rank carry**(`chunk_p_size > 1`):块 k 在 rank `k % P`。每个 local batch 解码后,各 rank 把本块
  `direct[:, -1:]`(inactive rank 发同形零张量)经 `exchange_chunk_boundary(carry, chunk_p_group)` 发给下一 rank。
  接收规则镜像上游 `run_causal_layers`:rank r>0 用收到的作本块 carry;rank 0 把收到的(来自 rank P-1)存给
  **下一个 batch**,本 batch 用上一 batch 存下的;全局 chunk.index==0 的 carry 恒为 None。
- 帧数:融合后整体比直相提前一帧(首块 -1 帧、末块 +1 帧)。写出帧数按 `chunk.output_range(raw, frames_to_trim)`
  平移计算,分段 writer 的 `frame_counts` 用同样的值。硬判据:成片帧数 == 源帧数(1 卡/4 卡、1 块、块数<卡数)。
- 删除 HEAD 的 `_seg_barrier/_partition_chunks/_concat_segment_parts`/ffprobe 校验/gloo group/`seed_temporal_offset`
  (上游 `chunk.start // 4` 直接给全局 RoPE 位置)。不设 `_rank_local_collectives`。
